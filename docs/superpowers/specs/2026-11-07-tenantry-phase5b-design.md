# Tenantry — Phase 5b design: Standard → Enterprise migration and scoped console access

Date: 2026-11-07 · Status: draft for review

## Purpose

Phase 5b finishes Phase 5. An operator moves a Standard workspace into a realm of its own without changing anyone's Tenantry user id or losing any of the workspace's data. Owners of an enterprise workspace let chosen admins of their own into their realm's Keycloak admin console, limited to people and groups.

The domain design comes from the project plan doc ("Phase 5"), ADR-0004 (one account per realm), ADR-0007 (our own user ids plus identities), ADR-0010 (realm templates) and ADR-0024. Company-login self-service is not in 5b and stays in `docs/known-issues.md`.

## What Keycloak 26.8.1 does (probed on throwaway realms)

- **Bridge.** An OIDC identity provider in realm B that signs in through realm A works with a pre-link. The pre-link is `POST /users/{id}/federated-identity/{alias}` with A's user id. The person clicks the provider's button on B's sign-in page, enters their A password, and lands at B's client with a code. No first-broker-login page appears and no second B account is created.
- **Fine-grained admin permissions v2** (`adminPermissionsEnabled`).
  - **Permissions written against the `tenantry-console` group allow:**
    - Users: `view`, `manage`, `reset-password`, `manage-group-membership`;
    - Groups: `view`, `view-members`, `manage-membership`.
  - **What the group's members could do with their own token:**
    - list, create and edit people;
    - reset passwords;
    - add people to `tenantry-admins`.
  - **What answered 403:**
    - role mapping and impersonation;
    - clients, realm settings and identity providers.
  - **Owner protection.** A second permission names owner user ids, with a negative policy on the same group, for scopes `manage`, `reset-password`, `manage-group-membership`, `impersonate` and `map-roles`. Editing, resetting or deleting those users then answers 403, and they stay visible. A matching deny on the `tenantry-console` group's `manage-membership` stops console users from handing out console access.
  - **Starting the console.** It loads (`whoami` 200) when the person also holds realm-management `query-users` and `query-groups`, and signs in through the realm's `security-admin-console` client.

## Decisions taken for this phase

| Topic                 | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Who moves a workspace | An operator: `pnpm ops enterprise migrate --tenant <slug> [--dry-run]`, then later `--finish`, or `--abort` before the cut-over. The commands call operator endpoints on the base domain, for `tenantry-ops` only, like provisioning. Every step can run again; a failed run is finished by running it again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Dry run               | Lists the members with their roles, pending invites, company logins (and any whose secret Tenantry does not hold), branding, and the realm that will be made. Changes nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Freeze                | The move sets the tenant's status to `migrating`. Member, role, invite, branding and company-login changes then answer 409 "This workspace is moving to Enterprise. Try again in a few minutes." Reads and projects keep working, and shared-realm sign-in keeps working until the cut-over.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| The realm             | `ent-<slug>`, built by the existing provisioning steps from the current template (v4), with the workspace's name and branding colour. The first-owner email step is skipped: owners arrive as people (next row).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| People                | Every organization member is created in the new realm with the same email, first and last name, email verified, and the same role (`owner`, `admin`, `member`, or none). A person who exists already, by email, is reused. Each gets an `identities` row from (new issuer, new Keycloak id) to the **same** `users.id`. The shared-realm identity row stays, because the person may belong to other workspaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Pending invites       | Re-sent as enterprise invites (an account with the role, plus a set-password email). The old rows are marked revoked with `via: 'migration'`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Bridge                | A confidential client `tenantry-bridge-<slug>` in the `platform` realm. Its secret is in the secrets store under `ent-<slug>/tenantry-bridge`, never in Postgres. The new realm gets an OIDC identity provider `tenantry-account`, shown as "Continue with your Tenantry account", with PKCE and the shared realm's keys. Every migrated person is pre-linked to their shared-realm account, so their old password works. The provider's first-broker-login flow is `tenantry-bridge-first-login`, which contains only Keycloak's "Deny access" step: anyone who isn't pre-linked is refused, and no stranger with a shared-realm account can make themselves an account in the customer's realm.                                                                                                                                                                                                           |
| Company logins        | Keycloak masks an identity provider's client secret (`**********`); `GET /clients/{id}/client-secret` returns only a realm client's own secret, and a company login's secret belongs to a client in the company's system. So from 5b, `pnpm ops idp link` keeps the secret it is given in the secrets store under `platform/idp-<alias>` (ADR-0023; store keys are `<realm>/<name>`), never in Postgres, logs or audit. The move copies each of the workspace's company logins into the new realm with its alias, URLs, client id, mappers and that secret, enabled, and pre-links the people who signed in through it. A login linked before 5b (acme's, in the seed) has no kept secret: it is copied **disabled**, the dry run and migrate output name it, and `pnpm ops enterprise idp-secret --tenant <slug> --alias <alias>` reads the secret from stdin, keeps it, sets it and enables the provider. |
| Cut-over              | One transaction, after every copy step has succeeded: `tenant_identity` gets the new realm, issuer and template version, and `kc_org_id` is cleared. The tier becomes `enterprise` and the status `active`. Audit `tenant.migrated` records counts only: people, invites, company logins. From then on a shared-realm token for this workspace gets 401 (the issuer rule), and both apps' sign-in goes to the new realm through the tenant's auth config.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Finish                | `--finish` removes the bridge provider and its platform client, deletes the organization from the `platform` realm (its people keep their shared-realm accounts), and stamps the migration finished. It is the operator's call when to finish: until then, people can still use the bridge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Abort                 | `--abort` is allowed before the cut-over only. It deletes the half-built realm, its secrets and the bridge client, then returns the tenant to `active` Standard. The organization was never touched, so nothing is lost. After the cut-over there is no way back (known issue).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Migration record      | `tenant_migrations` (forced RLS), one row per tenant: `from_org_id`, `realm`, `started_by` (operator, so null with `via: 'ops'`), and timestamps `started_at`, `cut_over_at`, `finished_at`, `aborted_at`. Steps decide whether they are done from Keycloak's state and this row, never from memory.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Template v4           | v3 plus `adminPermissionsEnabled: true`, admin events on (with representations, so edits made in the console are kept in Keycloak), the group `tenantry-console`, and the console permissions and policies from the probe. `ops enterprise upgrade` brings existing realms (Initech) to v4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Console access: who   | An owner turns **Console access** on or off per person on the Members page of an enterprise workspace, for owners and admins only. `POST`/`DELETE /api/members/:userId/console`, `tenant:settings`. Our row (`tenant_console_access`, forced RLS), the person's membership of `tenantry-console`, and the realm role `tenantry-console-user` (whose composite holds `query-users` and `query-groups`; built that way because, with permissions v2 on, the provisioner may grant a plain realm role but no realm-management role, ADR-0026) change in one request. Audit `console.granted` / `console.revoked`. A Keycloak refusal rolls the row back.                                                                                                                                                                                                                                                       |
| Console access: what  | People and groups only, as probed. Clients, flows, realm settings, identity providers, role mappings and impersonation are out of reach. Membership of `tenantry-console` can't be changed from the console.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Owners protected      | The owner-deny permission names the realm's current owners. Tenantry rewrites it in the same request as anything that changes who is an owner: a role change, a removal, an invite as owner, provisioning, migration and upgrade.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Losing the role       | Changing a person with console access to `member`, or removing them, also revokes console access (audited `console.revoked` with `reason: 'role'`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Getting in            | Members page and Dashboard show console users a link to `<auth>/admin/<realm>/console/`. They sign in with their usual account, and their realm's two-step rules apply.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Console audit         | Console edits are Keycloak admin events, not Tenantry audit entries. This is recorded in known issues. Tenantry's audit has the grant and revoke.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Standard workspaces   | No console access: 404 "Console access is available on Enterprise workspaces."                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Exit criteria

1. On a fresh seeded stack, a Standard workspace (`globex`, for the demo; the isolation suite uses one it makes itself) is moved with `pnpm ops enterprise migrate --tenant globex`.
   - An existing member signs in to both apps through "Continue with your Tenantry account" with their old password, with the same role, and sees the same projects and audit log.
   - A shared-realm token for `globex` gets 401.
   - `--finish` removes the bridge and the organization.
2. A migrate run that fails at any step finishes when run again. `--abort` before the cut-over leaves `globex` exactly as it was.
3. An Initech owner gives an admin console access. The admin opens the console, edits a member, resets a member's password and adds a member to `tenantry-admins`. They cannot edit or reset an owner, add anyone to `tenantry-console`, or open clients, realm settings or identity providers.
4. The new README rows are `tested`.
5. `pnpm lint typecheck test build`, `pnpm test:scripts`, `pnpm smoke`, `pnpm seed` twice (the second changes nothing) and `pnpm test:isolation` pass, locally and in CI.

## Data model

- `tenants.status` also allows `migrating`.
- `tenant_migrations`: `tenant_id` (RLS, primary key), `from_org_id`, `realm`, `started_at`, `cut_over_at`, `finished_at`, `aborted_at`.
- `tenant_console_access`: `tenant_id` (RLS), `user_id` → `users`, `granted_by` → `users`, `granted_at`; primary key (`tenant_id`, `user_id`).

## Testing

- **Keycloak contract**, run against the fake and real Keycloak:
  - the bridge: client, provider, deny-flow and pre-link, all idempotent;
  - only a pre-linked person gets through, and a stranger is refused;
  - the console permissions and the owner deny list, each rewrite replacing the last;
  - copying a company login with its kept secret (enabled), and without one (disabled), then setting the secret;
  - `ops idp link` keeps the secret in the secrets store and nowhere else.
- **API integration, against the fakes:**
  - the dry run;
  - the full move: identities point at the same `users.id`, roles carry over, invites are re-sent;
  - a failure injected at each step, then a rerun that finishes;
  - abort before the cut-over, and 409 after it;
  - the freeze returns 409 on people changes;
  - console grant and revoke: owners only, admins and owners only, audited, Standard 404, the role-change revoke, and the owner-deny rewrite on role changes.
- **Web:** the Members page console toggle and the console link.
- **Isolation suite**, on the full stack:
  - a Standard workspace made in the test is moved, and its member signs in through the bridge with their old password, with the same role and data;
  - a stranger with a shared-realm account is refused by the bridge;
  - a shared-realm token for that workspace gets 401;
  - a console user can't edit an owner, can't grant console access, and can't reach clients or realm settings;
  - Initech's console user can't see another realm.

## Risks

| Risk                                                                 | Mitigation                                                                                                                                            |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| A stranger uses the bridge to get an account in the customer's realm | Its first-broker-login flow denies everyone who isn't pre-linked; isolation test                                                                      |
| A console user takes over an owner (resets their password)           | The owner deny list is rewritten on every owner change; contract and isolation tests                                                                  |
| A console user hands out console access                              | `tenantry-console` membership is denied in the console; only Tenantry changes it                                                                      |
| A change made during the move is lost                                | The freeze refuses people changes while `migrating`                                                                                                   |
| A half-done move leaves a workspace unusable                         | Shared-realm sign-in keeps working until the cut-over; rerun to finish, or `--abort`                                                                  |
| A company login stops working after the move                         | Its secret is kept at link time and copied; one linked before 5b is named by the dry run and copied disabled and pre-linked, waiting for `idp-secret` |
| Console edits bypass Tenantry's audit                                | Keycloak admin events are on with representations; known issue                                                                                        |
| A kept company-login secret leaks                                    | Secrets store only, like realm secrets (ADR-0023); never in Postgres, logs, audit or API responses                                                    |
