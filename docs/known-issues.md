# Known issues and open items

The honest list of what does not work yet, what is missing, and what waits on a decision. Each phase adds to it and strikes out what it fixes. Decisions themselves live in [the ADRs](decisions/README.md) and each phase's spec.

Last updated: end of Phase 3 (2026-11-03).

## Known limitations

| Area                  | What happens                                                                                                                                                                                                                                                                                   | Planned fix                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Members               | Lists and owner counts read at most 1,000 members from Keycloak.                                                                                                                                                                                                                               | Paging, Phase 6                                  |
| Keycloak client edits | Each tenant's address is added to the SPA clients by one API process at a time; two API replicas could lose each other's edits.                                                                                                                                                                | Database lock or a provisioning worker, Phase 6  |
| Keycloak client size  | Every tenant adds a redirect URI to the SPA clients; thousands may slow Keycloak.                                                                                                                                                                                                              | Measured with the realm-count tests, Phase 6     |
| Service account       | `tenantry-backend` holds `manage-realm` and `manage-clients`, broader than needed. `tenantry-ops` also holds `manage-users` and `view-users`, which only the dev seed's memberships use. In each enterprise realm, `tenantry-backend` holds `manage-users`, `view-users` and `manage-clients`. | Fine-grained admin permissions, Phase 6          |
| Invites               | Keycloak sends the invite email while our database transaction is open; if the audit write fails afterwards, a sent invite has no row.                                                                                                                                                         | Outbox, Phase 6                                  |
| Invites               | Keycloak 26.8 cannot withdraw a sent invitation; a revoked invite is enforced when the person first visits (they are removed again).                                                                                                                                                           | When Keycloak adds it                            |
| Dev realm             | `tenantry-isolation-tests` (password grant, fixed secret) is in the only realm file; production imports must not include it.                                                                                                                                                                   | Production realm template, Phase 6               |
| Tests                 | The default 30-second key-set refetch cooldown has no test asserting a single refetch.                                                                                                                                                                                                         | Phase 6                                          |
| Signup                | If marking a failed signup also fails, the original error is hidden in the log.                                                                                                                                                                                                                | Phase 6                                          |
| Tokens                | A role change takes effect in the token within five minutes; identity-changing endpoints already use the live role.                                                                                                                                                                            | By design (ADR-0019)                             |
| Single logout         | A tab that stays in front, with no API call, keeps working until its access token expires (at most five minutes); switching to it signs out at once.                                                                                                                                           | By design (ADR-0020)                             |
| Branding              | The colour is checked against white only. In the dark theme the same colour sits on a dark page, where it can read poorly.                                                                                                                                                                     | Check both themes, Phase 6                       |
| Company login         | Operators only (`pnpm ops`): no portal page, no way to unlink a provider, and a verified domain is never checked again.                                                                                                                                                                        | Self-service and re-checks, Phase 5              |
| Company login         | People from a linked domain join with no role; they need an invite (the seed sends one for `alice@acme.test`) or an admin to give one.                                                                                                                                                         | Default role per linked domain, Phase 5          |
| Branding              | Two colour saves at the very same moment can record a stale "from" colour in the audit entry.                                                                                                                                                                                                  | Later                                            |
| Login theme           | Only the login pages are themed; the Keycloak account console keeps Keycloak's look.                                                                                                                                                                                                           | Later                                            |
| Enterprise tenants    | Operators only (`pnpm ops enterprise`): no self-service signup, and no command to delete an enterprise tenant or its realm. A run that fails leaves the tenant `provisioning`, holding its address until the command is run again.                                                             | Later                                            |
| Enterprise tenants    | An enterprise account lives in one realm, so the workspace switcher shows only that workspace.                                                                                                                                                                                                 | By design (ADR-0004)                             |
| Enterprise members    | "Never signed in" means the account has no password yet; revoking an invite deletes only such an account.                                                                                                                                                                                      | Phase 5, with company login per realm            |
| Secrets               | Realm secrets are kept in a file store (one JSON file per realm in `.secrets/`), fit for development only.                                                                                                                                                                                     | Vault or a cloud secret manager, Phase 6         |
| Secrets               | The API container runs as root, so on Linux the files in `.secrets/` belong to root.                                                                                                                                                                                                           | Non-root images, Phase 6                         |
| Dev seed              | Enterprise realms refuse the password grant, so the seed sets Initech's colour and logo in the database (with an audit entry) instead of through the API.                                                                                                                                      | By design (dev only)                             |
| Dev data              | Integration tests leave workspaces in the dev database; `pnpm ops tenants sync-origins` then registers their addresses with Keycloak, and `pnpm ops enterprise upgrade` lists their enterprise realms (which exist only in the test fake) as could not be read.                                | Test database separate from the dev one, Phase 6 |

## Fixed

| Phase | What was wrong                                                                                                                 | Fix                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| 3     | Email and display name were copied on first sign-in and never refreshed; anyone who opened a tenant address got a `users` row. | Both refresh on every sign-in, and a row is made only for a member.  |
| 3     | The header's product-name link reloaded the page.                                                                              | It navigates within the app.                                         |
| 3     | No test guarded that a company identity provider cannot bring an email outside the organization's domain.                      | A browser-level guarantee test.                                      |
| 2     | A Keycloak outage outside signup answered 500 instead of 502.                                                                  | Every Keycloak failure answers 502.                                  |
| 2     | A plain member could not leave a workspace.                                                                                    | `DELETE /api/members/me`, not the last owner.                        |
| 2     | AGENTS.md hard rule 2 named `organization.<alias>.realm_access`; the code reads `.groups`.                                     | Rule reworded.                                                       |
| 2     | The audit log showed raw ids; breadcrumbs reloaded the page; "Load more" had no busy state.                                    | Target names, router breadcrumbs, a loading indicator.               |
| 2     | `ops idp link` could adopt, and on failure delete, a Keycloak identity provider it had not created.                            | It refuses an alias it did not create, and undoes only what it made. |
| 2     | Any network error when a window regained focus signed people out.                                                              | Only Keycloak's `invalid_grant` ends the session.                    |
| 2     | Domains were stored as typed (`acme.test.` and `acme.test` were two).                                                          | One lower-case spelling, and non-domains refused.                    |
| 2     | The login theme showed branding fetched from any host named in the login URL.                                                  | Only addresses under the base domain count.                          |
| 2     | `ops idp link` took the client secret on the command line.                                                                     | `--client-secret-env` names the variable that holds it.              |
